# Architecture reviews

One file per review run with `/improve-codebase-architecture`, named `YYYY-MM-DD-architecture-review`: a `.md` record (the candidates, the decision on each, and links to the spec, plan and issue it produced) and the `.html` report the review generated.

When a review leads to a decision, update its record in the same change as the spec or plan, so the trail from "friction found" to "design approved" to "issue" is in one place. Specs and plans live in [../specs](../specs) and [../plans](../plans).
