# Plan: add accounts and categories from Settings (spec 2026-11-16-add-accounts-categories)

Branch `feat/add-accounts-categories`. One commit per task, each test-first. Verify with `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm test`, `pnpm exec playwright test` before the review.

## Tasks

1. **Layout in one place.** `schema.ts`: add `ACCOUNTS` (`tab`, `firstRow: 2`, `lastCol: 'E'`, `max: 40`) and `CATEGORIES` (`tab`, `firstRow: 2`, `lastCol: 'C'`, `maxExpense: 30`, `maxIncome: 15`), taking the caps from `template/build-template.gs`. Point the existing `REFERENCE.accounts`/`categories` ranges at them. Test: `schema.test.ts` asserts the caps equal the template constants (read the script text, so a change in one place fails the test).
2. **Pure validation** `src/lib/newItem.ts` + test: `validateNewName(name, existing, cap)` returns `ok` or a reason (`empty`, `tooLong`, `duplicate`, `full`). Trim; case-insensitive duplicate; accounts compared across every row, categories only within the same type; a leading `=`, `+`, `-` or `@` is refused. Cases: duplicate differing in case and spaces, 41st account, 16th income category but a free expense slot, emoji and accented names accepted.
3. **Store seam.** `store.ts`: `addAccount(a: {name, currency})` and `addCategory(c: {name, type})` returning `{ ok: true } | { ok: false, reason: 'Duplicate' | 'Full' }`. Fake store parity if one exists in `devFake`.
4. **Sheets adapter** (`ledgerStore.ts`) + tests against `fakeSheets`: read the name column and the tab guard in one `batchGet`, run `validateNewName` against the fresh data, compute the first free row (last row holding a name, plus one; a gap row inside the list is not reused), write `A:E` (`name, currency, true, true, true`) or `A:C` (`name, type, true`) as RAW with `valuesBatchUpdate`, grow the tab on the `grid limits` 400 as `appendRows` does, read the cell back and report `Duplicate` if a concurrent device won the row, mark the cache dirty and notify. Tests: first row on an empty list; row after the last; duplicate and full refused with no write; a concurrent same-name write returns `Duplicate`; nothing is written to any other tab or to column J; one read and one write per call; a read-only or unrecognised book refuses before any write (`checkVersion`).
5. **App state** (`app.svelte.ts`): `addAccount`/`addCategory`, serialised through the existing settings queue (`writeSetting`-style: needs connection and sign-in, one at a time), refresh the book on success, message on failure; returns the result so the form can show the reason. Tests in `app.add.test.ts` including offline refusal, duplicate message, and that `app.lists` shows the new item after success.
6. **UI.** `AddItemForm.svelte` used by both folds (name, a currency or type select, Add button; Enter submits; keeps the typed name on failure); wire into the Accounts and Categories folds in `SettingsScreen.svelte`; all text in `messages.ts`; 44px targets (360px e2e). After a successful add the new row is visible in the fold.
7. **Docs and checks.** `docs/corner-cases.md` (concurrent same name, no budget until set in `Budgets`, no undo), `docs/verification-checklist.md` item, CHANGELOG `[Unreleased]`, Playwright test (add an account and a category, see them in Add; refuse a duplicate).

## Risks to watch in review
- The free-row rule on the real template: `Accounts`/`Categories` may hold rows with checkbox validation but empty names; writing to the first row after the last name keeps them intact.
- `Categories` names are unique per type but the Ledger `category` column holds only the name; a category with the same name in both types is already allowed by the sheet, so it is allowed here.
- Writing booleans RAW: confirm the checkbox cells read TRUE/FALSE (not text) on the live copy.
