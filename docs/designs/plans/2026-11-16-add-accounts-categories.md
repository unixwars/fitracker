## Tasks

1. **Layout in one place.** `schema.ts`: `ACCOUNTS` (`tab`, `firstRow: 2`, `lastRow: 41`, `lastCol: 'E'`, `headers`, `max: 40`) and `CATEGORIES` (`tab`, `firstRow: 2`, `lastCol: 'C'`, `headers`, `maxExpense: 30`, `maxIncome: 15`); point the existing `REFERENCE` ranges at them. Test: `schema.test.ts` reads `template/build-template.gs` and asserts caps, `trimRows(MAX_ACCOUNTS + 1)` and the `HEADERS` equal these values.
2. **Pure validation** `src/lib/newItem.ts` + test: `normaliseName` (trim, NFC) and `validateNewName(name, rawRows, kind)` returning `ok` or one of `empty | tooLong | invalidChars | duplicate | full`. Cases: case and space differences; NFD "é" against NFC "é"; a 233-byte name and 100 CJK characters; `*`, `?`, `~`, leading `<`, `>`, `=`, `+`, `-`, `@`; accounts counted from non-empty names in A (inactive and bad-currency rows included); categories counted by active rows of that type; the 16th income category refused while an expense slot is free.
3. **Fake sheets: per-tab row limits** (`fakeSheets.ts`) so a 41-row `Accounts` can sit next to a 1000-row `Ledger`; test the 400 "grid limits" per tab. Needed by task 4.
4. **Store seam and Sheets adapter together** (one commit so types never break): `store.ts` `addAccount` / `addCategory` returning `{ ok: true } | { ok: false, reason }` with the reason set from task 2 plus `tryAgain`; the adapter per the spec's write path; `devFake` implements the same methods on the fake sheet. Tests against `fakeSheets`: first row on an empty list; row after the last name; a row with a currency but no name is not overwritten; checkbox-only rows are not "used"; refusals (`duplicate`, `full`, `invalidChars`) write nothing; **Accounts never grows** (a gap row is reused when A and B are empty, otherwise `Full`, no `growTab`); Categories grows once on grid limits; header mismatch or missing header refuses with `UnrecognisedLayout` and no write; a concurrent write of a different name to the same row retries the next row and succeeds; of the same name reports success for that device and no second row; request count is asserted as the real number (guard `batchGet`, write, read-back, plus `checkVersion` at most every 5 minutes) and `growTab` is not called for Accounts; no cell outside `A:E` / `A:C` and no other tab is written; a read-only or unrecognised book refuses before any write.
5. **App state** (`app.svelte.ts`): `addAccount` / `addCategory` through the settings write queue; success once the read-back confirms; the background refresh's failure is not reported as "not saved"; offline or signed-out refusal; a same-name exact match after a lost response counts as success. ## Risks to watch in review
- The free-row rule on the real template: `Accounts`/`Categories` may hold rows with checkbox validation but empty names; writing to the first row after the last name keeps them intact.
- `Categories` names are unique per type but the Ledger `category` column holds only the name; a category with the same name in both types is already allowed by the sheet, so it is allowed here.
- Writing booleans RAW: confirm the checkbox cells read TRUE/FALSE (not text) on the live copy (the review expects JSON `true` with RAW to be a boolean).
- SUMIFS criteria in the views and `Balances` (wildcards and comparison operators) are why name rules are stricter than a plain text field.
